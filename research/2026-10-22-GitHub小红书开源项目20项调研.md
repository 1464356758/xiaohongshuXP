# GitHub 小红书创作项目 20 项深度调研

> 研究日期：2026-10-22；面向项目 xiaohongshuXP。资料来自 GitHub 仓库 README、开源许可标识、仓库元数据与公开平台治理信息。**未逐一部署/端到端实测**，下列优缺点为文档与架构评估，不能当作功能实测通过报告。

## 研究结论

**不建议一键克隆某个“大而全”系统。** 值得组合的是 Easel 的工程架构、EthanYoQ 的账号与品牌锚点、NimaChu 的人物一致性、xuboboo 的事实/原创/合规质检、LuKK/MarkCard/NowhereMan 的确定性排版、mengke-wang 的IP选题规划。发布层保持人工确认、真实身份与真实素材，不将全自动托管作为产品目标。

筛选原则：从公开的候选仓库中选出 **20 个有明确 MIT/Apache-2.0/GPL-3.0 开源许可证**的代表，覆盖完整工作台、文案选题、生图、排版、发布、检索与数据。GitHub Star 是 2026-10-22 查询时的**快照**，不是质量保证。所谓“优点”是适用价值，“缺点”包括模型依赖、场景错配、合规和运行风险。

## 要避开的五个共性陷阱

1. **README的“全自动”≠已实测可用**：登录Cookie、网页DOM、平台审核与API都可能变化；需集成测试后才可上线。
2. **公开可读≠可商用开源**：商业系统优先 MIT/Apache-2.0；GPL组件需要核实衍生分发义务；图片、商品包装、字体还有独立权利。
3. **只优化文案不够**：美妆真实商品的名称/色号/规格、包装形态、肤感宣称、PERSONA一致性和实际成片审核才是核心。
4. **只靠LLM主观打分不够**：需要可追踪的证据、尺寸与文字越界机械检查、人工视觉验收、失败局部重做。不能无限循环重写造成高成本。
5. **全自动代发不应成为默认路径**：小红书于2026年3月10日发布AI托管运营账号治理公告，明确指出模拟真人、非真实创作和虚假互动问题，存在限流与封号风险。官方公告报道：https://www.thepaper.cn/newsDetail_forward_32741496 。

## 面向美妆IP的专项门禁

- 商品身份证据（品牌、全称、规格、色号、官网或官方店链接、图片许可证/素材来源）；无法核实则暂缓。
- 人物锚点：使用经过用户授权的固定 PERSONA，面部比例/发色/小痣方向一致，不镜像；独立真实像素审核。
- 图像：统一3:4竖版，可配置为 1086×1448；每页按5张产品图卡定义（不是把海报模板直接套在主图上）。
- 审核：每页给文字事实、商品结构、人物身份、排版边界、视觉营销表达的核查结果；最多3轮定向返修，未过则人工裁决。
- 版本：每次模型调用应有唯一 request_id、用量、输入版本及结果文件引用；幂等重试避免一次任务反复扣费。
- GitHub：文案、结构、任务单、哈希、审核报告为唯一事实源；大型图片可用受控对象存储并在仓库保存索引与校验值；API密钥不进GitHub。
